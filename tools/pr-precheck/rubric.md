# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
| --- | --- | --- | --- |
| diff-matches-plan | The accepted plan's scope, named files, exclusions, and deviation notes read side by side with the candidate diff's changed files and substantive hunks. | Every substantive change falls within the accepted plan or an explicit deviation that states what changed and why. Planned work is present, or an explicit deviation narrows or defers it without misrepresenting the remaining outcome. Undisclosed extra work, silently omitted work, or a diff that implements a different approach fails. | required |
| description-matches-change | The PR title, summary, issue reference, changes list, testing claims, reviewer notes, and stated deviations read against the issue, plan, diff, and test evidence. | The title and description accurately identify the issue, implemented behavior, changed areas, verification, and material limitations. Every factual claim is supported by the diff or captured evidence. A disclosed bounded shortfall passes when it is consistent with the accepted plan and the visible diff; possible effects in unshown files or callers are not evidence of a contradiction. An overclaim, false fidelity claim, or description of work visibly absent from the diff fails. | required |
| reproduction-proven | The plan's issue-specific test plan and original reproduction read against the candidate's before-and-after evidence, including the commands or steps, observed output, tested path, and expected result. | The evidence exercises the behavior the change is meant to alter and shows a specific observable result that distinguishes the reproduced failure from the post-change behavior. In an eval bundle, concise annotations count when they identify concrete output, errors, values, or behavior tied to named commands; a full terminal transcript is not required. In live mode, the captured command output must be present. A justified equivalent reproduction may pass. Vague statements such as "tested locally" or "works now," or evidence exercising only an unchanged control path, fail. | required |
| required-checks-reported | The plan's regression checks and the repository's required checks read against the candidate test evidence and truthful checklist state. | Every applicable planned or repository-required check has a named invocation and a specific visible outcome. In an eval bundle, a concise result such as a named suite passing with a count, or a named formatter or linter reported clean, is sufficient unless the package contradicts it; do not require line-by-line stdout. In live mode, require the actual captured output requested by the course workflow. A failing or unavailable check may still satisfy evidence reporting when stated honestly with its result and reason, unless the result demonstrates that the change violates a required behavior. A hidden, skipped, vague, or merely asserted check fails. | required |
| diff-reviewable | The complete unified diff and commit list, including all changed files and hunks. | The intended change is visible and reviewable without unrelated edits or debris. There are no debug prints, dead helpers, commented-out attempts, unexplained generated files, broad formatting churn, drive-by refactors, or unrelated feature changes. Necessary mechanical changes pass when their purpose is clear and they remain inside the plan. | required |
| template-complete | The repository facts, PR template, contribution guide, and candidate description and diff, including issue-closing syntax, required sections, checklists, tests, documentation, changelog, or other named artifacts. | Every applicable template section and repository ask receives real, truthful content. A checklist response may state completion, identify an item as not applicable with a valid reason, or explain why no diff is expected. Do not demand a separate artifact for a validly non-applicable item or fail a claim unless the package contradicts it. Required applicable artifacts must exist in the diff. Boilerplate, missing required sections, a blank issue reference, unsupported checked items, or a claimed applicable artifact absent from the diff fails. | required |
| policy-compliant | The repository's stated contribution and AI-use policies, explicit maintainer directions, Path Review house rules in live mode, and the candidate title, description, branch context, and disclosure. | The package follows every applicable policy and explicit direction, including an own-words AI-use disclosure whenever the stated policy requires one. Do not invent a disclosure requirement where no policy applies. Ignoring a stated policy, required disclosure, or explicit maintainer direction fails. | required |

## Verdict rule

Return `accept` only when every required check passes.

Return `reject` when any required check is `fail` or `unclear`.
`Unclear` means the evidence required to apply the check is genuinely
missing or too ambiguous to verify; it does not mean the evaluator
skipped the comparison.

All checks in this rubric are required. If preferred checks are added
later, they may be reported but must never change the verdict.
